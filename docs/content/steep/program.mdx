title: Program and messages
description: Send messages to the program, quit it, and test what your model does without a harness.
---

Prefer keys and clicks, since they test what a user does. These are for what's hard to reach that way. They need a `tea.Program`, so an [exec harness](/steep/harnesses#exec-harness) can't use them.

## SendProgram

`SendProgram` sends a message straight to the program, as something outside it would, such as a `tea.Program.Send` from a background goroutine:

```go
h.SendProgram(dataLoadedMsg{rows: rows}).Wait("42 rows")
```

Since input goes through the terminal, mixing the two can deliver them out of order. See [Ordering](/steep/input#ordering).

## QuitProgram

`QuitProgram` asks the program to shut down gracefully. You only need it to check what happens next, since the cleanup stops the program anyway:

```go
h.QuitProgram().WaitFinished()
```

## Sleep

`Sleep` lets the program run for a while, such as to hold on a screen in a recording.

```go
h.Sleep(500 * time.Millisecond)
```

Don't use it to wait for something to happen. It either wastes time or isn't long enough on a slow machine. [Wait for what you expect](/steep/checks#waiting-and-settling) instead.

## Reaching the session

`Session` returns the [`reel.Session`](/reel/sessions) your program runs in, for what the harness doesn't wrap, such as writing raw bytes to the terminal:

```go
h.Session().Write([]byte(ansi.SetModeInBandResize))
```

## Messages and the model

The harness tests your program from outside, as a user would: through the screen it draws. It doesn't keep the messages your model receives, or let you reach into the model. A test that checks those is tied to how the model works inside, and breaks when you change its messages without changing what it does.

To check something the screen doesn't show, such as the state a command leaves behind, test the model without a harness. Call `Update` as the program would, and send the message a command returns rather than waiting for it:

```go
func TestUpdate(t *testing.T) {
	m := NewModel()
	if _, cmd := m.Update(tea.KeyPressMsg{Code: tea.KeyEnter}); cmd == nil || m.brew != "Sencha" {
		t.Fatalf("brew = %q, want Sencha to start brewing", m.brew)
	}
	for m.brewing != 0 {
		m.Update(brewTick{})
	}
	if len(m.Served) != 1 {
		t.Errorf("served = %v", m.Served)
	}
}
```

If a test really needs the messages, such as to check how input reaches the program, wrap your model in one of your own that records them before it passes them on.
