## A settle that never settles

The screen was still changing when the timeout came, usually because of a spinner or a clock. Use `Wait` or [`WaitSettleMessages`](/steep/checks#settling-on-messages). The `(for 100ms)` is the quiet period it was looking for.

## An output that doesn't parse

An entry in `STEEP_EXPORT` that doesn't parse fails the test when the harness starts, so a typo can't lose you a recording. The rest of the variables are more forgiving: a value that doesn't parse is ignored.

## A hook's error

An error from a [hook](/steep/debugging#hooks) fails the test immediately.

## A program that fails

`WaitFinished` and `FinalModel` fail with `the program failed:` if the program returned an error other than `tea.ErrProgramKilled`, or if it panicked. So does `Close`, so a failed program fails the test even if nothing waited for it.

Bubble Tea catches a panic in `Update`, `View`, or a command, and prints `Caught panic:` and a stack to the test's output, so look there for where it happened.

## A test that panics

The cleanup still runs, so the recording is written, and `test panicked` is added to the result. `go test` prints the panic and its stack as usual.

## go test -timeout

`go test` kills the whole process when its timeout passes, before any cleanups run. Nothing is written, and the output shows only the stacks of the running goroutines. Keep [the harness's timeout](/steep/checks#the-timers) well below it.

## Troubleshooting

### A test fails, or is flaky

#### It passes alone and fails in CI

Most flaky tests check something before the program has drawn it.

- **`Assert` right after an input.** The program hasn't redrawn yet. Use `Wait`. See [Assert vs Require vs Wait](/steep/checks#choosing).
- **The timeout is too short.** The default is 2s, and a loaded CI machine can take longer. Set `STEEP_TIMEOUT=30s` on the job, and see if the failures go away.
- **`Sleep` instead of a wait.** It only works if the machine is fast enough. [Wait for what you expect](/steep/checks#dont-sleep).
- **`WaitSettle` returned too early.** If the program does something slow before redrawing, the screen looks settled. Wait for the text.

#### A wait times out, but the text is on the screen

Look at the `last output` in the failure.

- **The text is styled in pieces.** It doesn't matter for `Wait`, which checks the screen's text.
- **The text is wrapped or cut off.** It has to be on the screen in one piece. Check the terminal's size, or use `WithWindowSize`.
- **It appeared and went away.** Waits see the current screen. If a message shows briefly, wait for what follows it, or open the [recording](/steep/debugging#step-through-a-failure-in-the-inspector).
- **A wide character.** Text is compared as the screen has it. Check for a character that looks like the one you typed.

#### A key seems to be ignored

- **The program wasn't ready.** A key sent before the program has set up its screen may go to the wrong place. `Wait` for the screen first.
- **The name is wrong.** An unknown key name fails the test, but `Type("\n")` and `Key("enter")` aren't always the same to a program. Use `Key`.
- **A mode can't encode it.** Combinations such as `ctrl+shift+a` need the kitty keyboard protocol, and fail without it.

#### A mouse click does nothing

Your program must ask for the mouse, with `view.MouseMode`, or events are dropped. See [Mouse](/steep/input#your-program-must-ask-for-the-mouse). Also check the coordinates, which start at 0. `Locate` avoids having to know them.

#### Snapshots fail in CI but pass locally

- **Colors.** A JSON snapshot's colors depend on the color profile. Set `WithColor` explicitly.
- **The environment.** A program under `NewExecHarness` sees the host's environment, including `TERM` and `NO_COLOR`.
- **Times, paths, and names.** Anything from the machine ends up in the snapshot. Pass in fixed values, or use `snapshot.WithTransform`.
- **Line endings.** Check `.gitattributes` on Windows runners. Snapshots are compared with LF.

#### The snapshot's numbers changed

Each snapshot in a test takes the next number, so a new one in the middle renumbers the rest. [Name them with a suffix](/steep/snapshots#several-in-one-test).

### Nothing was recorded

Go through these in order:

1. **Is there a policy?** Without `STEEP_EXPORT_MODE` or `WithExport*`, nothing's written.
2. **Did the test fail?** `failure` mode writes nothing for a passing test.
3. **Was it removed?** Look for `is removed when the test ends` in the output. Pass `-artifacts`, or set `STEEP_EXPORT_DIR`.
4. **Are you looking in the right directory?** A relative `STEEP_EXPORT_DIR` is relative to each test's package directory. The test logs each path it wrote, with `-v` or on failure.
5. **Was it killed?** A `go test -timeout` writes nothing. See [the cases](/steep/recording#the-cases).

### An export failed

#### ffmpeg, `reel.ErrRawOutput`, and exports reel refuses

See [reel's troubleshooting](/reel/troubleshooting), which these come from. A profile with `effects.Redact` can't [also write `.cast`](/steep/recording#redacting-secrets).

#### A mark is missing

A profile looked for a mark the recording doesn't have. See [Missing marks](/steep/debugging#missing-marks).

#### The recording is too fast to follow

Recordings play in real time, and a test takes milliseconds. See [How recording works](/steep/recording#what-this-means-for-your-tests).

#### The colors look wrong

The default is a 256-color terminal, so Bubble Tea downsamples 24-bit colors. Use `steep.WithColor(steep.ColorTrueColor)`.

#### Icons or emoji are boxes

reel embeds a font, but not every glyph. See [Fonts](/reel/rendering#fonts) to add a Nerd Font, or `STEEP_RENDERER_FONT_FAMILY` to change it for one run.

### Getting help

Open [an issue](https://github.com/lrstanley/steep/issues) or ask on [Discord](https://liam.sh/chat). A `.cast` of the failure helps a lot, if there's nothing secret in it.
